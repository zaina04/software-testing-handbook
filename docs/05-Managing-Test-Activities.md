# Chapter 5: Managing Test Activities

## What is Test Management?

Test management is the process of planning, organising, monitoring, and controlling testing activities. Its goal is to ensure testing is completed efficiently and that the software meets the required quality standards.

---

## Test Planning

A test plan defines how testing will be carried out.

A typical test plan includes:

- Testing objectives
- Scope of testing
- Test strategy
- Resources and responsibilities
- Schedule
- Risks
- Entry and exit criteria
- Deliverables

Good planning helps avoid delays and ensures everyone understands the testing process.

---

## Risk-Based Testing

Risk-based testing prioritises testing based on the likelihood and impact of failures.

High-risk areas should receive more testing than low-risk areas.

Examples of high-risk features:

- Payment processing
- User authentication
- Medical software
- Banking transactions

---

## Test Monitoring and Control

### Test Monitoring

Test monitoring tracks testing progress using predefined metrics.

Examples include:

- Number of test cases executed
- Number of passed and failed tests
- Defects found
- Test coverage

### Test Control

If testing is not progressing as planned, corrective actions are taken.

Examples include:

- Reassigning resources
- Updating the test schedule
- Prioritising critical test cases

---

## Entry and Exit Criteria

### Entry Criteria

Conditions that must be met before testing begins.

Examples:

- Requirements are approved.
- Test environment is ready.
- Test data is available.

### Exit Criteria

Conditions that must be be met before testing ends.

Examples:

- Critical defects have been fixed.
- Required test coverage has been achieved.
- All planned test cases have been executed.

---

## Test Completion

Once testing is finished, the team reviews the results and documents what was achieved.

Typical completion activities include:

- Confirming exit criteria are met
- Preparing the final test report
- Documenting lessons learned
- Archiving test artefacts for future use

---

## Configuration Management

Configuration management ensures that the correct versions of software, test cases, test data, and documentation are used during testing.

It helps prevent issues caused by testing the wrong version of the software.

---

## Defect Management

A defect management process helps track defects from discovery to resolution.

A typical defect lifecycle is:

1. Defect identified
2. Defect reported
3. Defect assigned
4. Defect fixed
5. Defect retested
6. Defect closed

Clear defect reports help developers reproduce and fix issues quickly.

---

## Test Metrics

Test metrics measure the effectiveness and progress of testing.

Common metrics include:

- Test execution progress
- Pass/fail rate
- Defect count
- Defect severity
- Test coverage

Metrics help teams make informed decisions about software quality and release readiness.

---

# Chapter Summary

- Test management ensures testing is organised and completed effectively.
- Test planning defines the testing approach, schedule, resources, and objectives.
- Risk-based testing focuses on the areas with the highest business impact.
- Test monitoring measures progress, while test control takes action when needed.
- Entry criteria define when testing can begin, and exit criteria determine when it can finish.
- Configuration management ensures the correct versions of software and test artefacts are used.
- Defect management tracks issues from discovery to closure.
- Test metrics help evaluate testing progress and software quality.
